Fetch a single order by its CSBoard order id. The response includes the full per-item breakdown with delivery status, return reasons, and Steam trade offer details.

**Authentication required.** Send your key as `Authorization: Bearer csb_pub_...`.

## Path parameters

<ParamField path="id" type="string" required>
  The CSBoard order id, e.g. `ord_01J9Z3K8Q2`.
</ParamField>

## Response fields

The response is a single `Order` object with the same shape as the items in [`GET /v1/orders`](/api-reference/get-orders):

<ResponseField name="order_id" type="string" required />
<ResponseField name="steam_id" type="string | null" />
<ResponseField name="status" type="string" required>
  One of: `completed`, `hold`, `delivering`, `pending`, `cancelled`, `failed`.
</ResponseField>
<ResponseField name="custom_id" type="string | null" />
<ResponseField name="currency" type="string" required>
  Always `"USD"`.
</ResponseField>
<ResponseField name="charged_total_usd" type="number" required />
<ResponseField name="item_count" type="integer" required />
<ResponseField name="hold_until" type="datetime | null" />
<ResponseField name="delivery_type" type="string">
  `instant` or `manual`. `manual` means a person sends the trade, up to 12 hours, and the order may stay `delivering` that long with no trade offer. A P2P lot is always `manual`.
</ResponseField>
<ResponseField name="delivery_deadline_at" type="datetime | null">
  Delivery deadline, set only while `status` is `pending` or `delivering` (`null` on held orders). If the seller misses it, the order is cancelled and refunded automatically. See [`POST /v1/orders/{id}/cancel`](/api-reference/post-orders-cancel).
</ResponseField>
<ResponseField name="fail_reason" type="string | null">
  Why the order failed, as a code to branch on, such as `recipient_inventory_private` or `listing_gone`. Set only when `status` is `failed` or `cancelled`. The [list of codes](/api-reference/get-orders#fail-reasons) may grow — treat a value you do not know as `unavailable`.
</ResponseField>
<ResponseField name="fail_side" type="string | null">
  Who has to act on the failure: `recipient`, `seller`, `buyer` or `market`. Set only when `status` is `failed` or `cancelled`.
</ResponseField>
<ResponseField name="fail_message" type="string | null">
  One English sentence saying what happened and what to do. Show it as is; branch on `fail_reason`, since the wording can change.
</ResponseField>
<ResponseField name="refund" type="Refund | null">
  Money credited back for this order, or `null` if none was. Carries `amount_usd`, `refunded_at`, and `partial`. A `cancelled` or `failed` order is always refunded — read this instead of inferring it from the status.
</ResponseField>
<ResponseField name="created_at" type="datetime" required />
<ResponseField name="updated_at" type="datetime | null" />
<ResponseField name="items" type="OrderItem[]" required>
  Per-item breakdown. Each item has `market_hash_name`, `price_usd`, `status` (`hold` | `delivering` | `delivered` | `returned`), `tradable_at`, `return_reason`, `steam_trade_offer_id`, and `steam_trade_offer_finished_at`.
</ResponseField>

## Example request

```bash
curl https://csboard.com/v1/orders/ord_01J9Z3K8Q2 \
  -H "Authorization: Bearer csb_pub_..."
```

## Error codes

| HTTP status | Code | Meaning |
|---|---|---|
| 401 | `missing_api_key` / `invalid_api_key` | Missing or invalid API key. |
| 404 | `order_not_found` | No order exists for that id. |
| 429 | `rate_limit_exceeded` | Too many requests. Back off for the `Retry-After` header value. |
