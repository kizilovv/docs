The orders endpoint lets you buy between 1 and 10 listings in a single atomic request. The charge is debited from your CSBoard balance at the **live** asking price at the moment of execution — not at the price you saw when you queried `/v1/listings`. To protect yourself from price movements between lookup and purchase, always include `max_price_usd` as a total ceiling. The endpoint is idempotent: retrying with the same `Idempotency-Key` replays the original order rather than creating a duplicate charge.

**Authentication required.** Send your key as `Authorization: Bearer csb_pub_...`.

**Trading capability required.** The API key must have buying enabled. Configure this in your CSBoard profile.

## Prerequisites

Before placing an order, ensure:

1. **Trading-enabled key** — buying must be turned on for your API key in your CSBoard profile settings.
2. **Linked Steam account and trade URL** — your CSBoard account must have a Steam account connected with a valid trade URL so items can be delivered.
3. **Sufficient balance** — your CSBoard balance must cover the total cost of the items at their live prices.

## Request headers

<ParamField header="Idempotency-Key" type="string">
  Optional, 8–128 characters (e.g. a UUID) identifying this order attempt. If you retry a request with the same key, the server answers `200` with the header `Idempotent-Replayed: true` and the original order response instead of executing a second purchase. While the first request is still running, a retry answers `409 idempotency_in_progress`. Use this to safely retry on network timeouts without risk of double-charging.
</ParamField>

## Request body

<ParamField body="item_ids" type="string[]" required>
  Array of 1–10 unique listing IDs to purchase. Obtain these from the `id` field of `GET /v1/listings` responses. Each ID must appear only once per request.
</ParamField>

<ParamField body="max_price_usd" type="number">
  Total price ceiling in USD, enforced atomically at execution time. If the live total of all items exceeds this value, the entire order is rejected with a `price_moved` error and you are not charged. **Strongly recommended** — without it you have no overcharge protection.
</ParamField>

<ParamField body="idempotency_key" type="string">
  Alternative to the `Idempotency-Key` header. If both are provided, the header takes precedence. Use one or the other, not both.
</ParamField>

<ParamField body="appId" default="730" type="integer">
  Game the `item_ids` belong to: `730` = CS2, `570` = Dota 2, `252490` = Rust. Omit it for CS2. Send the same `appId` you read the ids with from `GET /v1/listings`. Check `tradable` in [`GET /v1/games`](/api-reference/get-games) to see where your key can buy.
</ParamField>

## Response fields

A new order answers **`201 Created`**. An idempotent replay answers `200` with the same body.

<ResponseField name="order_id" type="string" required>
  Unique identifier for this order. Pass it to `GET /v1/orders/{id}` to follow delivery.
</ResponseField>

<ResponseField name="status" type="string" required>
  The order's internal state when the response was built, for example `paid` or `pending_delivery`. This is not the normalised `status` vocabulary of `GET /v1/orders` — read the order there, or use [webhooks](/guides/webhooks), to follow it.
</ResponseField>

<ResponseField name="currency" type="string" required>
  Always `USD`.
</ResponseField>

<ResponseField name="charged_total_usd" type="number" required>
  Total debited from your balance, in USD.
</ResponseField>

<ResponseField name="item_count" type="integer">
  Number of items in the order.
</ResponseField>

<ResponseField name="items" type="object[]">
  One entry per item bought.

  <Expandable title="Item object">
    <ResponseField name="market_hash_name" type="string | null">
      Steam market hash name of the item.
    </ResponseField>
    <ResponseField name="price_usd" type="number | null">
      What this item was charged, in USD.
    </ResponseField>
    <ResponseField name="status" type="string | null">
      Internal item state, if one is set yet — usually `null` right after purchase.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="delivery" type="string | null" required>
  How the order is being delivered, when known: `instant` (bot delivery) or `pending` (a seller or supplier still has to send the trade). Dota 2 and Rust orders always answer `pending`.
</ResponseField>

<ResponseField name="expected_minutes" type="integer | null" required>
  Rough delivery estimate in minutes, when we can state one. Always `null` for Dota 2 and Rust orders.
</ResponseField>

<ResponseField name="created_at" type="datetime">
  ISO 8601 timestamp of when the order was created.
</ResponseField>

<ResponseField name="updated_at" type="datetime | null">
  ISO 8601 timestamp of the order's last change.
</ResponseField>

## Example request

```bash
curl -X POST https://csboard.com/v1/orders \
  -H "Authorization: Bearer csb_pub_..." \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 6f9c2b10-1a2b-4c3d-8e4f-5a6b7c8d9e0f" \
  -d '{
    "item_ids": ["itm_8841201", "itm_8841340"],
    "max_price_usd": 30.00
  }'
```

## Error codes

| HTTP status | Code | Meaning |
|---|---|---|
| 400 | `invalid_request` | Malformed body — `detail` is the field-error map. |
| 400 | `unsupported_item` | An id that cannot be bought through the API. Use ids from `GET /v1/listings`. |
| 400 | `steam_account_required` | No linked Steam account or valid trade URL on your CSBoard account. |
| 400 | `cannot_mix_sources` / `one_external_per_order` | These items cannot share one order. Split it. |
| 400 | `unsupported_game` | Your key cannot buy in this `appId`. `supported_app_ids` lists the games it can buy in. |
| 401 | `missing_api_key` / `invalid_api_key` | Missing or invalid API key. |
| 402 | `insufficient_balance` | Your balance is too low. The body carries `required_usd` and `current_usd`. |
| 402 | `kyc_required` | The purchase needs identity verification first. The body carries `kyc_url`. |
| 403 | `trading_not_enabled` | The API key does not have buying enabled. Enable it in your profile. |
| 403 | `account_restricted` | The account is restricted. Contact support. |
| 409 | `price_moved` | The live total exceeded `max_price_usd`. Order rejected; no charge made. The body carries `quoted_max_usd`, `current_total_usd` and the live price of each item. |
| 409 | `item_unavailable` | An item sold before your order landed. The body may carry `unavailable_ids`. |
| 409 | `idempotency_in_progress` | A request with this `Idempotency-Key` is still running. Wait and retry with the same key. |
| 409 | `pending_trades_limit` | The recipient has too many unaccepted Steam offers. `limit` is in the body. |
| 409 | `price_updating` / `concurrent_update` | Prices are mid-refresh, or a concurrent order won the race. Nothing was charged — retry. |
| 429 | `rate_limit_exceeded` | Over 250 orders/min, or over your key's general per-minute limit. Wait for the `Retry-After` header value. |
| 500 | `order_failed` | Unexpected failure. Check `GET /v1/orders/info` before retrying — the order may exist. |
| 503 | `market_unavailable` | The marketplace for one of the items is temporarily down. No charge was made. |
| 504 | `upstream_timeout` | The outcome is unknown. Re-send with the same `Idempotency-Key` or poll your orders — never with a new key. |

<Warning>
  Always include `max_price_usd` in your request. Prices on a live marketplace can change between the moment you query `/v1/listings` and the moment your order executes. Without this ceiling, your balance could be debited at a higher price than you intended, and there is no automatic rollback.
</Warning>

<Note>
  Items delivered via `hold` are subject to a Steam trade hold. Check the `tradable_at` field on the original listing (from `GET /v1/listings`) to see exactly when a held item will become tradable in your Steam inventory.
</Note>

<Note>
  **Dota 2 and Rust.** Orders with `appId` `570` or `252490` are queued for delivery and answer `delivery: "pending"` with `expected_minutes: null`. Follow them with [`GET /v1/orders/{id}`](/api-reference/get-order). The price ceiling, balance check and idempotency work exactly as for CS2.
</Note>
