Эндпоинт orders позволяет покупать от 1 до 10 листингов в одном атомарном запросе. Списание производится с вашего баланса CSBoard по **живой** цене продажи в момент исполнения — не по той цене, которую вы видели при запросе `/v1/listings`. Чтобы защититься от движений цены между запросом и покупкой, всегда указывайте `max_price_usd` как верхнюю границу итога. Эндпоинт идемпотентен: повтор с тем же `Idempotency-Key` воспроизводит исходный заказ, а не создаёт дубликат списания.

**Требуется аутентификация.** Отправьте ключ как `Authorization: Bearer csb_pub_...`.

**Требуется возможность торговли.** Для API-ключа должны быть включены покупки. Настройте это в профиле CSBoard.

## Предварительные условия

Перед оформлением заказа убедитесь, что:

1. **Ключ с включённой торговлей** — покупки должны быть включены для вашего API-ключа в настройках профиля CSBoard.
2. **Привязанный аккаунт Steam и trade URL** — к аккаунту CSBoard должен быть привязан аккаунт Steam с валидным trade URL, чтобы предметы можно было доставить.
3. **Достаточный баланс** — баланс CSBoard должен покрывать суммарную стоимость предметов по их живым ценам.

## Заголовки запроса

<ParamField header="Idempotency-Key" type="string">
  Необязательно, 8–128 символов (например, UUID) — идентификатор этой попытки заказа. Если вы повторяете запрос с тем же ключом, сервер отвечает `200` с заголовком `Idempotent-Replayed: true` и исходным ответом заказа вместо повторной покупки. Пока первый запрос ещё выполняется, повтор получает `409 idempotency_in_progress`. Так можно безопасно повторять запрос при сетевых таймаутах без риска двойного списания.
</ParamField>

## Тело запроса

<ParamField body="item_ids" type="string[]" required>
  Массив из 1–10 уникальных ID листингов для покупки. Получайте их из поля `id` ответов `GET /v1/listings`. Каждый ID должен встречаться в запросе только один раз.
</ParamField>

<ParamField body="max_price_usd" type="number">
  Верхняя граница итоговой цены в USD, проверяется атомарно в момент исполнения. Если живой итог по всем предметам превышает это значение, весь заказ отклоняется с ошибкой `price_moved` и списания не происходит. **Настоятельно рекомендуется** — без него у вас нет защиты от переплаты.
</ParamField>

<ParamField body="idempotency_key" type="string">
  Альтернатива заголовку `Idempotency-Key`. Если переданы оба, заголовок имеет приоритет. Используйте что-то одно.
</ParamField>

<ParamField body="appId" default="730" type="integer">
  Игра, к которой относятся `item_ids`: `730` — CS2, `570` — Dota 2, `252490` — Rust. Не передавайте поле для CS2. Отправляйте тот же `appId`, с которым получили id из `GET /v1/listings`. Где ваш ключ может покупать, показывает `tradable` в [`GET /v1/games`](/ru/api-reference/get-games).
</ParamField>

## Поля ответа

Новый заказ отвечает **`201 Created`**. Идемпотентный повтор отвечает `200` с тем же телом.

<ResponseField name="order_id" type="string" required>
  Уникальный идентификатор заказа. Передайте его в `GET /v1/orders/{id}`, чтобы следить за доставкой.
</ResponseField>

<ResponseField name="status" type="string" required>
  Внутреннее состояние заказа в момент формирования ответа, например `paid` или `pending_delivery`. Это не нормализованный словарь `status` из `GET /v1/orders` — следите за заказом там или через [вебхуки](/guides/webhooks).
</ResponseField>

<ResponseField name="currency" type="string" required>
  Всегда `USD`.
</ResponseField>

<ResponseField name="charged_total_usd" type="number" required>
  Сумма, списанная с вашего баланса, в USD.
</ResponseField>

<ResponseField name="item_count" type="integer">
  Количество предметов в заказе.
</ResponseField>

<ResponseField name="items" type="object[]">
  По одной записи на каждый купленный предмет.

  <Expandable title="Item object">
    <ResponseField name="market_hash_name" type="string | null">
      Steam market hash name предмета.
    </ResponseField>
    <ResponseField name="price_usd" type="number | null">
      Сколько списано за этот предмет, в USD.
    </ResponseField>
    <ResponseField name="status" type="string | null">
      Внутреннее состояние предмета, если оно уже задано; сразу после покупки обычно `null`.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="delivery" type="string | null" required>
  Способ доставки, если он уже известен: `instant` (доставка ботом) или `pending` (трейд ещё должен отправить продавец или поставщик). Заказы Dota 2 и Rust всегда отвечают `pending`.
</ResponseField>

<ResponseField name="expected_minutes" type="integer | null" required>
  Примерное время доставки в минутах, когда мы можем его назвать. Для заказов Dota 2 и Rust всегда `null`.
</ResponseField>

<ResponseField name="created_at" type="datetime">
  Временная метка ISO 8601 создания заказа.
</ResponseField>

<ResponseField name="updated_at" type="datetime | null">
  Временная метка ISO 8601 последнего изменения заказа.
</ResponseField>

## Пример запроса

```bash
curl -X POST https://csboard.com/v1/orders \
  -H "Authorization: Bearer csb_pub_..." \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 6f9c2b10-1a2b-4c3d-8e4f-5a6b7c8d9e0f" \
  -d '{
    "item_ids": ["itm_8841201", "itm_8841340"],
    "max_price_usd": 30.00
  }'
```

## Коды ошибок

| HTTP-статус | Код | Значение |
|---|---|---|
| 400 | `invalid_request` | Некорректное тело — в `detail` карта ошибок по полям. |
| 400 | `unsupported_item` | Этот ID нельзя купить через API. Используйте ID из `GET /v1/listings`. |
| 400 | `steam_account_required` | К аккаунту CSBoard не привязан Steam-аккаунт или нет валидного trade URL. |
| 400 | `cannot_mix_sources` / `one_external_per_order` | Эти предметы нельзя купить одним заказом. Разделите его. |
| 400 | `unsupported_game` | Ваш ключ не может покупать в этом `appId`. В `supported_app_ids` — игры, где покупать можно. |
| 401 | `missing_api_key` / `invalid_api_key` | Отсутствует или некорректный API-ключ. |
| 402 | `insufficient_balance` | Баланса не хватает. В теле — `required_usd` и `current_usd`. |
| 402 | `kyc_required` | Для покупки сначала нужна верификация личности. В теле — `kyc_url`. |
| 403 | `trading_not_enabled` | Для API-ключа не включены покупки. Включите их в профиле. |
| 403 | `account_restricted` | Аккаунт ограничен. Обратитесь в поддержку. |
| 409 | `price_moved` | Живой итог превысил `max_price_usd`. Заказ отклонён, списания не было. В теле — `quoted_max_usd`, `current_total_usd` и живая цена каждого предмета. |
| 409 | `item_unavailable` | Предмет продан раньше, чем пришёл ваш заказ. В теле может быть `unavailable_ids`. |
| 409 | `idempotency_in_progress` | Запрос с этим `Idempotency-Key` ещё выполняется. Подождите и повторите с тем же ключом. |
| 409 | `pending_trades_limit` | У получателя слишком много непринятых офферов Steam. Лимит — в поле `limit`. |
| 409 | `price_updating` / `concurrent_update` | Цены обновляются или параллельный заказ оказался быстрее. Ничего не списано — повторите. |
| 429 | `rate_limit_exceeded` | Более 250 заказов/мин или превышен общий лимит ключа в минуту. Подождите время из заголовка `Retry-After`. |
| 500 | `order_failed` | Непредвиденная ошибка. Перед повтором проверьте `GET /v1/orders/info` — заказ мог создаться. |
| 503 | `market_unavailable` | Маркетплейс одного из предметов временно недоступен. Списания не было. |
| 504 | `upstream_timeout` | Исход неизвестен. Повторяйте с тем же `Idempotency-Key` или опросите заказы — никогда с новым ключом. |

<Warning>
  Всегда указывайте `max_price_usd` в запросе. Цены на живом маркетплейсе могут измениться между моментом запроса `/v1/listings` и моментом исполнения заказа. Без этой верхней границы с баланса может быть списана более высокая сумма, чем вы планировали, и автоматического отката нет.
</Warning>

<Note>
  Предметы, доставляемые в режиме `hold`, попадают под торговый холд Steam. Проверяйте поле `tradable_at` исходного листинга (из `GET /v1/listings`), чтобы узнать, когда именно удерживаемый предмет станет доступен для обмена в вашем инвентаре Steam.
</Note>

<Note>
  **Dota 2 и Rust.** Заказы с `appId` `570` или `252490` ставятся в очередь на доставку и отвечают `delivery: "pending"` с `expected_minutes: null`. Следите за ними через [`GET /v1/orders/{id}`](/ru/api-reference/get-order). Верхняя граница цены, проверка баланса и идемпотентность работают так же, как для CS2.
</Note>
