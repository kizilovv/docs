Коннектор ботов позволяет одному мерчант-аккаунту продавать со многих Steam-аккаунтов: ваших собственных ботов или аккаунтов продавцов, с которыми вы работаете. Каждый подключённый аккаунт выставляет свои предметы на P2P-маркете CSBoard и сам отправляет трейд-офферы. Деньги со всех продаж приходят на один баланс, ваш.

Покупатели видят обычные P2P-лоты. Какому мерчанту принадлежит аккаунт, нигде не показывается.

<Note>
  Коннектор включается для каждого мерчант-аккаунта отдельно. Пока он не включён для вашего, все вызовы отсюда отвечают `403 listing_not_enabled`. Напишите нам, чтобы включить.
</Note>

## Два способа подтвердить продажу

Подключённому аккаунту не нужны ни расширение CSBoard, ни приложение. Вы выбираете, как мы подтверждаем его продажи:

| | Без ключа | С ключом чтения |
|---|---|---|
| Что вы даёте | трейд-ссылку аккаунта | трейд-ссылку и Steam Web API ключ аккаунта |
| Как подтверждается продажа | по вашему отчёту, который мы сверяем с публичным инвентарём аккаунта | мы сами читаем оффер в Steam |
| Выплата после принятия оффера | через 14 дней | обычный холд, около 7 дней |

Ключ необязателен, его можно добавить, заменить или стереть в любой момент. Больше режимы ничем не отличаются: лимитов на аккаунт нет ни в одном.

## Как это работает

<Steps>
  <Step title="Подключите аккаунт">
    ```bash
    curl -X POST https://csboard.com/v1/p2p/bots \
      -H "Authorization: Bearer csb_pub_..." \
      -H "Content-Type: application/json" \
      -d '{
        "trade_url": "https://steamcommunity.com/tradeoffer/new/?partner=914144835&token=Qh3xLm8a",
        "label": "склад 3"
      }'
    ```

    Инвентарь аккаунта должен быть публичным, а сам аккаунт должен использовать мобильный аутентификатор Steam. В ответе аккаунт со `status: "checking"`. Он станет `connected`, когда мы прочитаем его инвентарь, обычно в пределах минуты. До этого опрашивайте [`GET /v1/p2p/bots/{bot_id}`](#аккаунты).

    Steam-аккаунт, у которого уже есть собственный аккаунт CSBoard, подключить нельзя.
  </Step>
  <Step title="Выставьте его предметы">
    Пришлите цены для asset id, которые хотите продавать. Мы выставляем только то, что сами прочитали в инвентаре аккаунта.

    ```bash
    curl -X PUT https://csboard.com/v1/p2p/pool \
      -H "Authorization: Bearer csb_pub_..." \
      -H "Content-Type: application/json" \
      -H "Idempotency-Key: 6d1f0a52-9c3e-4b7a-8f10-2e5b7c9d4a61" \
      -d '{
        "bot_id": "cmx2k4p9d0001ab12cd34ef56",
        "mode": "replace",
        "items": [
          { "asset_id": "44120000001", "price_usd": 120.00 },
          { "asset_id": "44120000002", "price_usd": 8.45 }
        ]
      }'
    ```

    `mode: "merge"` выставляет и переоценивает то, что вы прислали. `mode: "replace"` делает то же и снимает все лоты этого аккаунта, которых в запросе нет, то есть один запрос задаёт всю полку. До 5 000 строк в запросе.

    Ответ `202` с `job_id`. Результат по каждой строке: `GET /v1/p2p/pool/jobs/{job_id}`.

    `price_usd` это цена для покупателя. `seller_payout_usd` у лота это то, что получите вы.
  </Step>
  <Step title="Примите продажу">
    Когда покупатель платит, продажа сразу принимается за аккаунт. Вы узнаёте о ней из вебхука [`p2p.sale.created`](#события-вебхуков) или опросом:

    ```bash
    curl "https://csboard.com/v1/p2p/sales?status=to_send" \
      -H "Authorization: Bearer csb_pub_..."
    ```

    В продаже к отправке есть `buyer.trade_url`, `asset_id`, текст `offer_message` для оффера и срок `send_deadline_at`.
  </Step>
  <Step title="Отправьте оффер и сообщите о нём">
    Ваш софт отправляет трейд-оффер с аккаунта, на котором лежит предмет, на `buyer.trade_url`, с текстом `offer_message`, до `send_deadline_at`. Затем сообщите номер оффера:

    ```bash
    curl -X POST https://csboard.com/v1/p2p/sales/sent \
      -H "Authorization: Bearer csb_pub_..." \
      -H "Content-Type: application/json" \
      -d '{ "trade_offer_id": "9443417618", "sale_ids": ["cmx3a1b2c0007ab12cd34ef56"] }'
    ```

    Один оффер может нести несколько продаж одного покупателя. Когда покупатель принял оффер, сообщите и об этом:

    ```bash
    curl -X POST https://csboard.com/v1/p2p/sales/cmx3a1b2c0007ab12cd34ef56/offer-state \
      -H "Authorization: Bearer csb_pub_..." \
      -H "Content-Type: application/json" \
      -d '{ "state": "accepted" }'
    ```

    Если у аккаунта сохранён ключ чтения, оба отчёта необязательны: мы сами находим оффер среди отправленных аккаунтом и следим за ним, а отчёт только заставляет нас посмотреть сразу.
  </Step>
  <Step title="Получите деньги">
    У принятой продажи `status: "delivered"` и дата `payout_at`. В этот день, после нашей проверки, что обмен не был отменён, `payout_usd` зачисляется на баланс мерчанта, а продажа становится `paid`.
  </Step>
</Steps>

## Ключ чтения

Steam Web API ключ позволяет нам читать трейд-офферы и историю обменов аккаунта, поэтому продажа подтверждается тем, что говорит Steam, и оплачивается по обычному холду. Ключ берётся на [steamcommunity.com/dev/apikey](https://steamcommunity.com/dev/apikey) под этим аккаунтом.

Передайте его при подключении аккаунта (`steam_web_api_key` и `consent_version` в `POST /v1/p2p/bots`) или позже:

```bash
curl -X PUT https://csboard.com/v1/p2p/bots/cmx2k4p9d0001ab12cd34ef56/credential \
  -H "Authorization: Bearer csb_pub_..." \
  -H "Content-Type: application/json" \
  -d '{ "steam_web_api_key": "<32 символа>", "consent_version": "2026-11-21" }'
```

`consent_version` подтверждает, что вы передаёте ключ на этих условиях:

- **Что вы передаёте.** Steam Web API ключ этого аккаунта.
- **Зачем.** CSBoard читает им ваши трейд-офферы и историю обменов, чтобы подтвердить продажу: оффер отправлен, принят, обмен не отменён за 7 дней.
- **Чего мы не делаем.** Не отправляем, не принимаем и не отменяем офферы, не входим в аккаунт. Сам ключ по правилам Steam позволяет отменять и отклонять офферы; передавать предметы и входить в аккаунт он не позволяет.
- **Хранение.** Ключ хранится зашифрованным, ключ шифрования лежит отдельно от базы данных. Каждое обращение к ключу записывается.
- **Отзыв.** `DELETE /v1/p2p/bots/{bot_id}/credential` стирает ключ сразу, аккаунт продолжает продавать без него. `DELETE /v1/p2p/bots/{bot_id}` стирает ключ и отключает аккаунт. У Steam ключ отзывается на steamcommunity.com/dev/apikey.
- **Если ключ перестал работать.** Аккаунт продолжает продавать в режиме без ключа. Открытые продажи не отменяются, выплата по ним идёт по сроку режима без ключа.

Перед сохранением мы проверяем ключ в Steam. Ключ, который Steam отклоняет, получает ответ `422 credential_rejected`, и ничего не сохраняется. Ни один вызов не возвращает ключ: у аккаунта видно только `credential.on_file`.

## Аккаунты

| Вызов | Что делает |
|---|---|
| `POST /v1/p2p/bots` | Подключить аккаунт по трейд-ссылке, с ключом или без |
| `GET /v1/p2p/bots` | Все подключённые аккаунты и что они делают |
| `GET /v1/p2p/bots/{bot_id}` | Один аккаунт |
| `PUT /v1/p2p/bots/{bot_id}/credential` | Добавить или заменить ключ чтения |
| `DELETE /v1/p2p/bots/{bot_id}/credential` | Стереть ключ, продолжать продавать |
| `DELETE /v1/p2p/bots/{bot_id}` | Отключить: ключ стёрт, лоты сняты с продажи |

```json
{
  "bot_id": "cmx2k4p9d0001ab12cd34ef56",
  "steam_id": "76561198874410563",
  "trade_url": "https://steamcommunity.com/tradeoffer/new/?partner=914144835&token=Qh3xLm8a",
  "label": "склад 3",
  "status": "connected",
  "status_reason": null,
  "status_changed_at": "2026-12-01T10:01:12.000Z",
  "proof": "public",
  "credential": { "on_file": false, "set_at": null, "last_ok_at": null },
  "payout_hold_hours": 336,
  "selling": true,
  "lots": 655,
  "lots_usd": 9871.36,
  "open_sales": 2,
  "delivered_30d": 148,
  "delivered_usd_30d": 2204.18,
  "failed_30d": 2,
  "send_median_seconds": 125,
  "created_at": "2026-12-01T10:00:00.000Z"
}
```

| `status` | Значение |
|---|---|
| `checking` | Подключён только что, читаем инвентарь. Если чтение невозможно, `status_reason` говорит почему, например `private_inventory` или `empty_inventory` |
| `connected` | Лоты аккаунта на продаже |
| `credential_error` | Steam отклоняет сохранённый ключ. Аккаунт продаёт в режиме без ключа, пока вы не замените или не сотрёте ключ |
| `disconnected` | Вы его отключили. Лоты сняты с продажи, цены сохранены; подключить снова можно через `POST /v1/p2p/bots` |

`proof` равен `key`, когда мы читаем офферы в Steam, иначе `public`. `payout_hold_hours` это число часов после принятия оффера, через которое продажа оплачивается; `null` означает обычный холд.

## Листинг

`PUT /v1/p2p/pool` это путь для пачки. Вызовы для одного лота из [инструкции по P2P-листингу](/ru/guides/p2p-listing) работают и для подключённого аккаунта: добавьте `?bot_id=` к `GET /v1/p2p/inventory`, `GET` и `POST /v1/p2p/listings`, `PATCH` и `DELETE /v1/p2p/listings/{id}`.

Результат задачи синхронизации:

```json
{
  "job_id": "cmx2m7q1r0004ab12cd34ef56",
  "bot_id": "cmx2k4p9d0001ab12cd34ef56",
  "mode": "replace",
  "status": "done",
  "accepted": 2,
  "listed": 1,
  "repriced": 0,
  "delisted": 0,
  "refused_count": 1,
  "refused": [
    {
      "asset_id": "44120000002",
      "code": "price_below_market",
      "detail": "price_usd 8.45 is under the minimum 9.1 for this item (market ~18.2). Listings made with an API key cannot go below it.",
      "market_usd": 18.2,
      "floor_usd": 9.1,
      "price_usd": 8.45
    }
  ],
  "error": null,
  "created_at": "2026-12-01T10:05:00.000Z",
  "finished_at": "2026-12-01T10:05:04.000Z"
}
```

| `code` строки | Значение |
|---|---|
| `asset_not_seen` | Предмета нет в нашем последнем чтении инвентаря аккаунта. Повторите синхронизацию, когда он там появится |
| `not_tradable` | Предмет сейчас нельзя выставить: он под трейд-блокировкой или уже в продаже |
| `price_below_market` | Цена ниже половины нашей рыночной цены предмета; в строке есть `floor_usd` |

Задача, которая не смогла начаться, говорит почему в `error`: `private_inventory`, `empty_inventory`, `inventory_unreadable`, `bot_disconnected`. Тот же `Idempotency-Key` с тем же телом возвращает ту же задачу; с другим телом ответ `409 idempotency_key_mismatch`.

Правила цен те же, что на P2P-маркете: доллары в целых центах, цена ниже половины нашей рыночной отклоняется.

## Продажи

| Вызов | Что делает |
|---|---|
| `GET /v1/p2p/sales` | Продажи всех подключённых аккаунтов. Фильтры: `status`, `bot_id`; страницы: `cursor`, `limit` (до 200) |
| `GET /v1/p2p/sales/{sale_id}` | Одна продажа |
| `POST /v1/p2p/sales/sent` | Оффер отправлен: `trade_offer_id`, `sale_ids`, необязательный `needs_confirmation` |
| `POST /v1/p2p/sales/{sale_id}/offer-state` | Оффер теперь `active`, `accepted`, `declined`, `canceled`, `expired`, `invalid_items` или `needs_confirmation` |
| `POST /v1/p2p/sales/{sale_id}/send-failed` | Steam отказал в отправке: `code`, необязательный `detail` |
| `POST /v1/p2p/sales/{sale_id}/decline` | Вы не будете доставлять эту продажу |
| `POST /v1/p2p/sales/{sale_id}/cancel-confirmed` | Вы отменили оффер, который мы просили отменить |

```json
{
  "sale_id": "cmx3a1b2c0007ab12cd34ef56",
  "status": "to_send",
  "cancel_requested": false,
  "bot_id": "cmx2k4p9d0001ab12cd34ef56",
  "listing_id": "cmx2m9t3u0005ab12cd34ef56",
  "asset_id": "44120000001",
  "market_hash_name": "AK-47 | Redline (Field-Tested)",
  "float_value": 0.1532,
  "paint_seed": 412,
  "currency": "USD",
  "price_usd": 120,
  "commission_usd": 2.4,
  "payout_usd": 117.6,
  "buyer": {
    "steam_id": "76561198000000777",
    "trade_url": "https://steamcommunity.com/tradeoffer/new/?partner=39735049&token=aB3dE6gH"
  },
  "offer_message": "CSBoard order #CD34EF56",
  "send_deadline_at": "2026-12-01T12:30:00.000Z",
  "accept_deadline_at": null,
  "trade_offer_id": null,
  "proof": "public",
  "delivered_at": null,
  "payout_at": null,
  "fail_reason": null,
  "created_at": "2026-12-01T12:00:00.000Z",
  "updated_at": "2026-12-01T12:00:00.000Z"
}
```

| `status` | Значение |
|---|---|
| `to_send` | Покупатель заплатил; отправьте оффер до `send_deadline_at` |
| `sent` | Оффер у покупателя, у него время до `accept_deadline_at` |
| `delivered` | Принято; идёт холд, `payout_at` говорит до какого момента |
| `paid` | `payout_usd` на вашем балансе |
| `cancelled` | Закрыто без доставки; `fail_reason` говорит почему. Покупателю вернули деньги |
| `rolled_back` | Обмен отменён в Steam. Ничего не выплачивается |
| `review` | Продажу смотрит человек с нашей стороны |

`fail_reason` принимает значения `seller_did_not_deliver`, `seller_cancelled`, `offer_declined`, `offer_expired`, `cancelled`, `rolled_back`.

`buyer` присутствует, только пока есть оффер, который надо отправить или за которым надо следить.

### Когда продажа идёт не так

- **Вы не можете отправить.** Сообщите об отказе Steam через `send-failed` или откажитесь от продажи через `decline`: отклонённая продажа закрывается, покупателю возвращаются деньги, штрафа нет. Если оффера нет к `send_deadline_at`, продажа закрывается: покупателю возвращаются деньги, а с вашего баланса списывается штраф, 4% цены, минимум $0.50. Штрафа нет, если отправке помешал Steam и вы об этом сообщили.
- **Мы просим отменить.** `cancel_requested: true` означает, что время покупателя вышло или заказ был завершён. Отмените оффер в Steam, затем вызовите `cancel-confirmed`. Предмет, который покупатель принял после этого запроса, не оплачивается.
- **Без ключа отчёт `accepted` проверяется.** Если предмет всё ещё в публичном инвентаре аккаунта, отчёт получит ответ `409 asset_still_in_inventory`.

## События вебхуков

Зарегистрируйте адрес, как описано в разделе [Webhooks](/guides/webhooks). К коннектору относятся четыре события:

| Событие | Когда | `data` |
|---|---|---|
| `p2p.sale.created` | Покупатель оплатил лот подключённого аккаунта | продажа |
| `p2p.sale.updated` | Продажа изменилась: статус, `cancel_requested`, оффер, `payout_at` | продажа |
| `p2p.bot.updated` | Аккаунт сменил статус или режим подтверждения | `bot_id`, `steam_id`, `label`, `status`, `status_reason`, `proof`, `credential.on_file` |
| `p2p.listing.updated` | Мы сняли лот с продажи, потому что предмет ушёл из инвентаря аккаунта | `id`, `bot_id`, `status`, `needs_resync`, `asset_id`, `market_hash_name`, `price_usd` |

`p2p.sale.created` отправляется сразу. Остальные три приходят в пределах минуты после изменения. Одно и то же состояние дважды не доставляется.

## Лимиты

Подключение, листинг и отчёты делят один лимит записи P2P на ключ: **30 запросов в минуту**. Один запрос пула на 5 000 строк считается одним запросом. Чтения идут по обычному минутному лимиту ключа. См. [Rate Limits](/ru/rate-limits).

## Ошибки

| HTTP-статус | Код | Значение |
|---|---|---|
| 403 | `listing_not_enabled` | Коннектор не включён для вашего аккаунта |
| 400 | `invalid_trade_url` | Это не трейд-ссылка Steam |
| 400 | `invalid_credential` | Это не Steam Web API ключ |
| 400 | `consent_required` | `consent_version` не передан или не актуален |
| 422 | `credential_rejected` | Steam отклоняет этот ключ; ничего не сохранено |
| 503 | `steam_unavailable` | Steam не ответил на проверку ключа; ничего не сохранено, повторите |
| 409 | `steam_account_in_use` | Steam-аккаунт подключён в другом месте или у него есть свой аккаунт CSBoard |
| 404 | `bot_not_found` | Такого подключённого аккаунта под вашим ключом нет |
| 409 | `bot_disconnected` | Аккаунт отключён |
| 404 | `sale_not_found` | Такой продажи под вашим ключом нет |
| 409 | `offer_not_reported` | Сначала сообщите об оффере через `sent` |
| 409 | `asset_still_in_inventory` | Предмет всё ещё в инвентаре аккаунта, значит оффер не принят |
| 409 | `idempotency_key_mismatch` | Этот `Idempotency-Key` уже использован с другим пулом |
