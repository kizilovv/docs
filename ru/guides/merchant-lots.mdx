Лоты мерчанта нужны продавцу, у которого предметы лежат на нескольких Steam-аккаунтах и есть свой софт для отправки трейдов. Вы присылаете нам **лоты**; мы выставляем их на P2P-маркет CSBoard; когда лот покупают, мы вызываем ваш сервер; вы отправляете оффер в Steam и сообщаете, что с ним стало.

Steam-аккаунты к CSBoard не подключаются: мы не просим ни логин, ни API-ключ, ни трейд-ссылку ваших аккаунтов.

<Note>
  По умолчанию выключено. Напишите нам, чтобы включить функцию для вашего мерчант-аккаунта, и пришлите три URL из раздела ниже.
</Note>

## Цифры

| | |
|---|---|
| Срок отправки оффера | **12 часов** с момента покупки, для любого лота |
| Срок приёма покупателем | 24 часа с момента отправки оффера |
| Отмена покупателем | через 30 минут, если оффера нет |
| Неотправка в срок | заказ отменяется, покупателю возврат. **Штрафа нет.** Срыв попадает в вашу статистику отправок |
| Комиссия | **1%** от цены продажи |
| Выплата | на баланс CSBoard через **14 дней** после приёма покупателем, если не возникло проблем |
| Выплата быстрее | присылайте со статусами refresh-токен Steam аккаунта-продавца: как только мы прочитаем сделку как завершённую после 7-дневной защиты Steam, продажа выплачивается без ожидания 14-го дня |
| Реверс с вашего аккаунта | покупателю полный возврат, мерчант-аккаунт закрывается навсегда, баланс замораживается |

Принимаются только предметы, доступные к обмену прямо сейчас (`assetType: 1`).

## Три URL на вашей стороне

| URL | Когда вызываем | Что вы отвечаете |
|---|---|---|
| **Order Create** | ваш лот покупают, до списания денег покупателя | `{"status": 1, "orderId": "<ваш id>", "errorMsg": ""}`, чтобы принять заказ; `status: 2`, чтобы отказать |
| **Order Details** | нам нужен текущий статус заказа | `{"requestId", "orderStatus", "reversedType", "tradeOfferStatus", "tradeOfferId"}`; `orderStatus: -1`, если заказ вам неизвестен |
| **Order Cancellation** | покупатель не дождался | `{"cancelSuccess": true, "message": ""}`; ответьте `false`, если оффер уже отправлен |

Все три вызова: `POST` с JSON в теле. На ответ Order Create у вас **5 секунд** (3 секунды, если покупатель пришёл с партнёрской площадки). Нет ответа вовремя = покупка не состоится. Поэтому предмет, выставленный на нескольких площадках, не продастся дважды: перед каждой продажей мы спрашиваем вас.

### Проверка наших вызовов

В каждом теле есть `sign`: возьмите остальные поля, отсортируйте по имени, соедините как `имя=значение` через `&`, добавьте `&sign=<ваш app secret>`, посчитайте MD5 в верхнем регистре. Значение `null` записывается строкой `null`.

```text
payPrice=12.34&productId=sku-1&requestId=ms3f9c...&tradeUrl=https://steamcommunity.com/tradeoffer/new/?partner=1&token=a&sign=<app secret>
```

То же тело подписано и в заголовке `X-CSBoard-Signature` (`t=<unix>,v1=<hex>`, HMAC-SHA256 от `<t>.<тело>` с тем же секретом), как наши вебхуки.

## Как проходит продажа

<Steps>
  <Step title="Выставьте лоты">
    ```bash
    curl https://csboard.com/v1/p2p/sell/create \
      -H "Authorization: Bearer csb_pub_..." -H "Content-Type: application/json" \
      -d '{
        "appId": 730,
        "assetType": 1,
        "products": [{
          "productId": "sku-1",
          "steamId": "76561198000000001",
          "assetId": "30000000001",
          "classId": "310777179",
          "instanceId": "0",
          "marketHashName": "AK-47 | Redline (Field-Tested)",
          "price": 12.34,
          "tradableTime": 0,
          "inspectUrl": "steam://rungame/730/..."
        }]
      }'
    ```

    `productId` — ваш собственный номер лота. До 100 лотов за вызов. Лот, который мы не можем принять, вернётся в `errorData.failList` с причиной; остальные приняты.

    Лот ещё не в продаже. Сначала мы сами читаем **публичный** инвентарь Steam-аккаунта и выставляем лот, когда увидели в нём предмет. Следите через `GET /p2p/sell/detail/{productId}`: `operationStatus` идёт от `100` (выставляется) к `101` (выставлен) или `102` (отказ, причина в `failedCode`).
  </Step>
  <Step title="Примите заказ">
    Мы вызываем ваш Order Create URL: `requestId` (наш номер продажи, используйте его во всех статусах), ваш `productId`, `payPrice` и `tradeUrl` покупателя. Ответьте `status: 1` и отправьте оффер в Steam на эту трейд-ссылку.
  </Step>
  <Step title="Сообщайте каждый статус">
    ```bash
    curl https://csboard.com/v1/p2p/order/status/notify \
      -H "Authorization: Bearer csb_pub_..." -H "Content-Type: application/json" \
      -d '{"requestId": "ms3f9c...", "orderStatus": 3, "tradeOfferId": "8123456789", "tradeOfferStatus": 2}'
    ```

    Один вызов на каждую смену статуса. Повтор безопасен.
  </Step>
  <Step title="Получите выплату">
    `GET /p2p/sell/order/list` показывает каждую продажу: наш `orderStatus`, нашу комиссию `fee` и `settleTime`, момент выплаты на баланс.
  </Step>
</Steps>

## Статусы заказа

| `orderStatus` | Значение | Что нужно |
|---|---|---|
| `1` | ждёт отправки | |
| `2` | оффер создан, ждёт вашего подтверждения в Steam | `tradeOfferId` |
| `3` | оффер отправлен, ждёт покупателя | `tradeOfferId` |
| `10` | покупатель принял | |
| `11` | отменён | если оффер был отправлен: `tradeOfferStatus`, состояние Steam, которым оффер закончился (`5` истёк, `6` отменён, `7` отклонён, `4` встречное предложение, `10` отменён вторым фактором) |
| `200` | защита Steam закончилась, сделку не откатили | |
| `220` | реверс | `reversedType`: `1` продавец, `2` покупатель |

`tradeOfferStatus` — это `ETradeOfferState` самого Steam.

Что мы делаем со статусом:

- `10` сверяем с публичным инвентарём продавца. Если предмет ещё там, статус отклоняется с `asset_still_in_inventory`.
- `11` после отправленного оффера не закрывает продажу только по вашему слову: сначала мы ищем предмет обратно в инвентаре продавца.
- `220` с `reversedType: 2` ставит продажу на ручную проверку. Выплаты по нему нет.

## Refresh-токен Steam

Добавьте `refreshToken` к статусу, чтобы мы прочитали эту одну сделку в Steam:

```json
{"requestId": "ms3f9c...", "orderStatus": 200, "refreshToken": "eyJ..."}
```

- Это должен быть **мобильный** refresh-токен того Steam-аккаунта, который отправил оффер.
- Мы используем его для одного чтения и забываем. Он не хранится, не попадает в логи, и мы не просим Steam его обновить, так что ваша копия остаётся рабочей.
- Со статусом `10` мы проверяем, что в оффере проданный предмет и что его принял покупатель этой продажи. Со статусом `200`, отправленным после окончания защиты Steam, читаем сделку: завершена — продажа выплачивается сразу; откатили — оформляется реверс.
- В ответе поле `tokenRead` говорит, что показало чтение: `accepted`, `complete`, `reversed`, `not_final` (рано, пришлите `200` позже), `mismatch` (токен другого аккаунта, либо оффер или сделка, в которых предмет этой продажи не ушёл её покупателю), `token_refused`, `unreadable`.

Токен необязателен. Без него продажа выплачивается на 14-й день.

Держите инвентарь аккаунта-продавца открытым до выплаты. На 14-й день мы смотрим в него ещё раз; если прочитать не удалось, выплата ждёт, и мы повторяем раз в час.

## Управление лотами

| Вызов | Что делает |
|---|---|
| `POST /p2p/sell/update` | новые цены; `requestId` делает повтор безопасным; в ответе `successList` и `failList` |
| `POST /p2p/sell/cancel` | снять лоты с продажи; лот, который покупают прямо сейчас, ответит `lot_in_trade` |
| `GET /p2p/sell/detail/{productId}` | один лот |
| `GET /p2p/sell/list` | ваши лоты и `deliveryInfo`: доля доставленных, среднее время отправки и число срывов за 7 и 15 дней |
| `POST /p2p/sell/price/reference` | наша минимальная цена в продаже по `marketHashName` |

`status` лота: `1` в продаже, `2` снят, `3` скрыт (мы перестали видеть предмет на аккаунте; вернётся сам), `4` в сделке, `5` продан.

Цена ниже половины нашей рыночной отклоняется с `price_below_market`, как у любого P2P-лота.

## Ответы

У всех ответов один вид:

```json
{"success": true, "data": {}, "errorCode": 0, "errorMsg": null, "errorData": null, "errorCodeStr": null}
```

При отказе `success` равен `false`, `errorCodeStr` — код для ветвления, `errorMsg` — то же словами.

| `errorCodeStr` | Когда |
|---|---|
| `selling_not_enabled` | лоты мерчанта не включены для этого аккаунта |
| `merchant_terminated` | аккаунт закрыт после реверса |
| `cooldown_not_supported` | предмет пока нельзя обменять |
| `steam_account_in_use` | с этого Steam-аккаунта уже выставляет другой аккаунт |
| `asset_already_listed` | предмет уже в открытом лоте |
| `asset_not_in_inventory` | мы не нашли предмет в публичном инвентаре аккаунта |
| `trade_offer_id_required` | `2`, `3` или `10` без оффера |
| `trade_offer_status_required` | `11` при отправленном оффере без состояния Steam |
| `order_not_delivered` | `200` или `220` раньше `10` |
| `rate_limit_exceeded` | больше 30 изменений лотов или 600 статусов в минуту |
