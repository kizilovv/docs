API CSBoard применяет лимиты запросов на каждый ключ, чтобы сохранять стабильность сервиса для всех пользователей. Если вы превышаете лимит, то сразу получаете ответ `429` — ни один запрос не обрабатывается частично. Реализуйте клиент так, чтобы он считывал заголовок `Retry-After` и делал паузу перед повтором, а не долбил эндпоинт в плотном цикле.

## Лимиты по эндпоинтам

Лимиты считаются **на API-ключ** в фиксированных минутных окнах: счётчик обнуляется в начале каждой минуты. Единственное исключение — фид цен без ключа: его лимит считается по IP-адресу.

| Лимит | Эндпоинт(ы) |
|---|---|
| **100 / мин** | Любой запрос с ключом — листинги, цены, игры, курсы валют, баланс, статус ордеров, управление вебхуками, P2P. Это значение по умолчанию; для отдельного ключа его можно повысить. |
| **250 / мин** | `POST /v1/orders` и `POST /v1/market/buy` (размещают ордера на покупку и расходуют реальные деньги). Эти запросы учитываются и в лимите на ключ выше. |
| **30 / мин** | P2P-записи — `POST /v1/p2p/listings`, `PATCH` и `DELETE /v1/p2p/listings/{id}` делят один бюджет. Пакет до 50 предметов считается одним запросом. Эти вызовы учитываются и в лимите на ключ выше. |
| **1 / мин** | `GET /v1/prices/snapshot.ndjson.gz` (массовый сжатый снапшот) |
| **3 одновременно** | Параллельные подключения к `GET /v1/listings/stream` на один ключ |
| **1 / мин на IP** | `GET /v1/public/prices` — без ключа, поэтому лимит привязан к вашему IP-адресу. Фид пересобирается раз в минуту, так что более частый опрос ничего не даёт. |

<Note>
  30 запросов с **неверными или отсутствующими API-ключами** с одного IP-адреса в течение минуты автоматически включают 5-минутный бан на уровне IP. Во время бана каждый запрос с этого IP получает `429 too_many_failed_auth`, какой бы ключ он ни содержал. Исправьте ключ и дождитесь окончания бана, прежде чем повторять запросы.
</Note>

<Tip>
  Самый дешёвый способ укладываться в лимиты — перестать опрашивать то, что мы можем присылать сами. [Вебхуки](/guides/webhooks) доставляют состояние ордера по мере изменений, а [SSE-стрим листингов](/ru/api-reference/get-listings-stream) присылает события `new` и `gone` по одному соединению — ни то ни другое не расходует бюджет запросов на каждое событие.
</Tip>

## Формат ответа 429

При превышении лимита на ключ API возвращает:

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 60
Content-Type: application/json

{ "code": "rate_limit_exceeded", "detail": "Rate limit of 100 requests/min exceeded." }
```

Значение заголовка `Retry-After` — целое число **секунд**. Для лимитов на ключ это `60`: такой паузы всегда достаточно, потому что счётчик обнуляется в начале следующей минуты.

Эндпоинт массового снапшота использует отдельный код ошибки при превышении лимита:

```json
{ "code": "snapshot_rate_limited", "detail": "Snapshot is limited to 1/min. Poll less or cache it." }
```

`GET /v1/public/prices` без ключа ограничивается по IP-адресу, а не по ключу, и в теле его ответа `429` нет поля `code` — ориентируйтесь на статус и `Retry-After`:

```json
{ "error": "Rate limit exceeded, retry in 37 seconds", "statusCode": 429 }
```

## Обработка 429 в клиенте

Считывайте `Retry-After` и спите как минимум столько секунд, прежде чем повторять запрос. Ниже показан простой цикл повторов на bash:

```bash
while true; do
  RESPONSE=$(curl -si https://csboard.com/v1/listings \
    -H "Authorization: Bearer csb_pub_...")

  STATUS=$(echo "$RESPONSE" | head -1 | awk '{print $2}')

  if [ "$STATUS" = "429" ]; then
    RETRY_AFTER=$(echo "$RESPONSE" | grep -i "retry-after" | awk '{print $2}' | tr -d '\r')
    echo "Rate limited. Waiting ${RETRY_AFTER}s..."
    sleep "$RETRY_AFTER"
  else
    echo "$RESPONSE" | tail -1  # print body
    break
  fi
done
```

<Tip>
  Добавьте небольшое случайное смещение (например, `sleep $((RETRY_AFTER + RANDOM % 5))`) при запуске нескольких воркеров параллельно, чтобы они не возобновляли работу одновременно и не срабатывали по лимиту снова.
</Tip>

## Повышение лимитов

Стандартные лимиты подходят для большинства интеграций, но если у вас сценарий с высокой нагрузкой — например, конвейер данных или высокочастотный торговый бот — [свяжитесь с нами](https://csboard.com), чтобы обсудить более высокий лимит на ключ для вашей учётной записи.
